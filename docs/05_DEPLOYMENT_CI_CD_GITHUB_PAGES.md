# 05 - Deployment, CI/CD & GitHub Pages
## Brandspace / Aixor Agency Next.js Static Website

This document provides a guide to the continuous deployment pipeline, GitHub Actions workflow configuration, and GitHub Pages setup.

---

## 1. CI/CD Workflow (`.github/workflows/deploy.yml`)

The repository includes a production-ready GitHub Actions workflow that automatically builds and deploys the static website whenever code or content is pushed to the `main` branch.

### Workflow Source
```yaml
name: Deploy Next.js Static Export to GitHub Pages

on:
  push:
    branches: ["main"]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: "20"
          cache: "npm"

      - name: Install dependencies
        run: npm ci --legacy-peer-deps

      - name: Build Next.js static site
        run: npm run build

      - name: Upload Pages artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: ./out

  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    needs: build
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

### Key Workflow Highlights
- **Triggers:** Fires on any push to `main` (including commits generated by Pages CMS) and supports manual triggers via `workflow_dispatch`.
- **Permissions:** Uses least-privilege security (`contents: read`, `pages: write`, `id-token: write`).
- **Dependency Caching:** Utilizes `actions/setup-node@v4` with npm package caching for build speeds under 60 seconds.
- **Artifact Isolation:** Only the pre-rendered `out/` folder is uploaded and served. Source code, TypeScript files, and development configurations are never exposed.

## 2. GitHub Repository Configuration Checklist

Before the workflow can successfully deploy to GitHub Pages, you must complete the following configuration in your GitHub repository:

### Step 1: Enable GitHub Actions as Pages Source
1. In your browser, navigate to your repository on GitHub:  
   `https://github.com/brandspacebd/brandspace-website/settings/pages`
2. Under **Build and deployment**:
   - In the **Source** dropdown, select **GitHub Actions**.  
   *(Do NOT select "Deploy from a branch").*

### Step 2: Verify Workflow Permissions
1. Go to **Settings** -> **Actions** -> **General**.
2. Scroll to **Workflow permissions**.
3. Ensure **Read and write permissions** is selected, and check **Allow GitHub Actions to create and approve pull requests**.
4. Click **Save**.

## 3. Important Note on Private Repositories & GitHub Pages

- **GitHub Pages Policy:** GitHub Pages is free for **public** repositories. For **private** repositories, GitHub Pages requires a GitHub Pro ($4/month), Team, or Enterprise account.
- **Options if on GitHub Free Plan:**
  1. **Option A (Recommended for client privacy):** Upgrade the GitHub organization/account to GitHub Pro.
  2. **Option B (Zero-cost alternative):** If you prefer not to pay for GitHub Pro while keeping the repository private, you can connect the same private repository to **Cloudflare Pages** or **Vercel** with zero monthly cost (set Build Command to `npm run build` and Output Directory to `out`).

## 4. Custom Domain Setup (e.g. `brandspace.com`)

If deploying to a custom domain:
1. In GitHub repo **Settings -> Pages -> Custom domain**, enter your domain name (e.g. `brandspacebd.com` or `agency.brandspacebd.com`).
2. In your DNS provider (Cloudflare, Namecheap, GoDaddy):
   - For an apex domain (`brandspacebd.com`), create 4 `A` records pointing to GitHub Pages IPs:
     - `185.199.108.153`
     - `185.199.109.153`
     - `185.199.110.153`
     - `185.199.111.153`
   - For a subdomain (`www` or `agency`), create a `CNAME` record pointing to:  
     `brandspacebd.github.io`
3. Check **Enforce HTTPS** in GitHub Pages settings once the DNS resolves.

## 5. Pushing Local Commits to GitHub

To push the local repository commits to GitHub:
```bash
# Push main branch to remote
git push -u origin main
```

If prompted for credentials:
- **Username:** `brandspacebd` (or your GitHub account username).
- **Password:** Enter a GitHub **Personal Access Token (classic)** with the `repo` scope enabled (generate one at [https://github.com/settings/tokens](https://github.com/settings/tokens)).
- Alternatively, authenticate via GitHub CLI: `gh auth login`.
